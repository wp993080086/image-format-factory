### A1 的核心问题：导出在 Android 上必坏且隐蔽

`file_selector` 的 `getSaveLocation` 在 Android 没有平台实现，直接 `throw UnimplementedError`，被 `EditorController` 的 `try/catch` 吞成「导出失败，请重试」。表现像偶发故障，实际是必现。

处置：Android 分支改走 `flutter_file_dialog` 的 `ACTION_CREATE_DOCUMENT`；`ExportService` 增加可注入的 `AppTarget`，否则该分支在测试里根本走不到。

### A7 的核心问题：错误码分级形同虚设

`E-EXPORT-001~005` 定义了却从未被抛出，磁盘满、只读目录、文件被占用都落到 006「请降低尺寸再试」——用户会照着去改尺寸，改多少次都没用。

处置：按 OS 错误码归类，并**按端分支**。同一个 errno 两端语义不同，这是最容易写错的地方：

| errno | Windows | POSIX |
|---|---|---|
| 13 | `ERROR_INVALID_DATA` | `EACCES`（权限不足） |
| 32 | `ERROR_SHARING_VIOLATION`（文件被占用） | `EPIPE` |

### 补记（2026-11-18）：WebP 导出与 HEIC 导入

这两项原计划推到 M4，实际已按 PRD 十二 ADR-010 落地。核心取舍：纯 Dart 路线走不通（`image` 包只有 webp **解码**器、无编码器；HEVC 解码没有纯 Dart 实现），因此引入原生库——Windows 端随包分发 libwebp / libheif，Android 端复用系统自带编解码器，零新增依赖。

| 项 | Windows | Android |
|---|---|---|
| WebP 导出 | FFI 直调 libwebp，编码在子 Isolate 内完成 | 平台通道 `Bitmap.compress(WEBP)` |
| HEIC 导入 | FFI 直调 libheif（内含 libde265 解 HEVC） | 系统 `BitmapFactory`（Android 8.0+） |

关键实现细节：

- **Windows 不能走 MethodChannel**：桌面 embedder 不支持后台 isolate 发平台消息，而 WebP 编码必须在编码子 Isolate 内完成，所以 Windows 只能用 FFI。
- **DLL 必须与 exe 同目录**：`DynamicLibrary.open` 按短名查找，而 Flutter 桌面 embedder 的工作目录不是 exe 目录，故 CMake 用 `install(FILES ...)` 复制到 exe 同级。
- **libwebp.dll 依赖 libsharpyuv.dll**：Windows 解析 DLL 依赖时搜的是「exe 所在目录」而非「webp.dll 所在目录」，故代码里先按短名预加载依赖，绕开搜索路径差异。
- **条件导出要两侧签名一致**：`heif_native.dart` / `webp_native.dart` 按 `dart.library.ffi` 分流 stub 与 FFI 实现，stub 版本必须保留 `libraryPath` 参数，否则 stub 端编译不过（这是本次分析报错的直接原因）。
- **许可必须随包**：libheif / libde265 是 LGPL-3.0，分发二进制时需附许可全文；`showLicensePage` 覆盖不到非 Dart 包，故在 `lib/app/native_licenses.dart` 单独声明并于关于页展示，许可文本同时放 assets 与发布目录的 `licenses/`。

## 七、判定

M2 的**代码交付**满足验收条件：构建通过、双端能力位如实、错误码分级可触发、桌面端主路径与全部功能分支已由用户手工验证。

**Android 端不能判定为验收通过**——它在模拟器/真机上一次都没跑过，SAF 落地、ICO 可见性、权限路径这三处恰恰只能在 Android 上暴露。补齐第四节 A1~A11 之前，M2 标记为「代码完成、待真机验收」。

**WebP 导出与 HEIC 导入**已交付并由单元测试覆盖真实 DLL 路径，但同样**未经 GUI 手工验收**：Windows 侧需补 2.11 / 5.6b~5.6d，Android 侧需补 A12~A18。两端都通过前，这两项功能标记为「代码完成、待手工验收」。

**发布合规**方面，原生库许可清单已补齐（`lib/app/native_licenses.dart` + assets 许可全文 + 发布目录 `licenses/`），满足 LGPL-3.0 的分发要求；HEVC 专利评估仍是待办，商用前必须处理。
