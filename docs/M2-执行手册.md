> 版本：v1.0（2026-11-11）
> 定位：把 M1 的 Windows 能力落到 Android，重点解决**导出通道缺失**与**导入过滤失效**两个平台级硬缺口。
> 使用方式：按 A0 → A7 顺序推进；每步「验证」不通过不得进入下一步。

## 1. 执行原则

1. **区分「代码可验证」与「仅真机可验证」**：后者一律进清单，不假装通过。
2. **能力位只写真实现过的东西**：`systemSavePanel` 之类的布尔值必须与代码行为一致，否则重复 S8 的 SVG 教训。
3. **不为未开工的端做特化**：鸿蒙整体还没跑起来，只把能力位如实标 false，不加实现。
4. **平台差异收敛在 service 层**：功能层不得出现 `Platform.isAndroid`。

## 3. 步骤详情

### A0 Android 构建基线

**问题（三层，逐个排）**

1. Gradle 发行包 zip 损坏：`zip END header not found`，wrapper 在解压一个 70MB 的不完整包。
2. **Kotlin 增量编译跨盘崩溃**：`IllegalArgumentException: this and base files have different roots` —— pub 缓存在 C 盘、工程在 F 盘，Kotlin 无法跨盘符计算相对路径。表现是 `Could not close incremental caches`，根因藏在 `Caused by` 的 `Suppressed` 里。
3. CMake 临时目录被上一次中断的构建留下的 daemon 锁住。

**处置**

| 改动 | 内容 |
|------|------|
| `android/gradle/wrapper/gradle-wrapper.properties` | `distributionUrl` 指向本机已有的 Gradle 发行包（`file:///…/gradle-9.1.0-all.zip`） |
| `android/gradle.properties` | 新增 `kotlin.incremental=false` 并注明跨盘原因（**已提交**） |

**验证**：`flutter build apk --debug` ✅ 66s，产出 `app-debug.apk`（164MB）。`flutter test` 238 仍全绿。

> `gradle-wrapper.properties` 是**本机环境专用**改动（绝对路径在他机不成立），**不纳入版本库**；仓库内维持官方 `distributionUrl`，换机器时自行放置发行包或改回官方地址。

---

### A1 导出通道（SAF）

**问题**：`ExportService.saveAs` 直接调 `file_selector.getSaveLocation`，而该接口在移动端走默认实现 `throw UnimplementedError`（`file_selector_platform_interface` 源码级核对，见 ADR-007）。Android 上导出必然失败。

**规格**

| 端 | 通道 |
|----|------|
| Windows | `file_selector.getSaveLocation` + 自行写盘（不变） |
| Android | `flutter_file_dialog.saveFile`（SAF `ACTION_CREATE_DOCUMENT`），由系统写盘 |
| 鸿蒙 | 抛出明确 `UnsupportedError`（`share_plus` 通道 M3 接） |

**动作**
1. `ImageFormatInfo` 加 `mimeType`（SAF 只认 MIME，不认扩展名）。
2. `ExportService` 加可选 `target` 参数（测试注入用），按端分派到 `_saveWithSaveDialog` / `_saveWithSystemDialog`。
3. `saveAs` 加可选 `mimeTypes`；`save()` 传 `[format.mimeType]`，诊断日志传 `['text/plain']`。

**实现取舍**
- **不抽象成策略接口**：只有两条路径，多一层抽象只会让「参数从哪来到哪去」更难追。
- **`target` 可注入**：本机平台探测永远是 Windows，不注入的话 SAF 分支一行都跑不到。
- **异常不细分错误码**：沿用 controller 的统一 `E-EXPORT-006` 兜底（与 M1 一致），细分成 001~005 记为遗留。

**验证**：`export_service_test.dart` 6 例 —— 走 SAF 且不碰 `getSaveLocation`、参数（文件名/字节/MIME）正确、取消返回 null、ICO 用 `image/x-icon`、诊断日志用 `text/plain`、桌面端不走 SAF。

---

### A2 导入 MIME 过滤

**问题**：`file_selector_android` 把 `extensions` 经 `MimeTypeMap` 转 MIME，**转换失败只打一条 warning 就丢弃**。`.ico` 在多数 ROM 的 `MimeTypeMap` 里不存在 → ICO 文件在选择器里直接不可见（PRD 十章标 Android 支持 ICO）。

**动作**
1. 把类型过滤器抽成 `ImportService.importTypeGroup()`，同时给 `extensions` 与 `mimeTypes`。
2. MIME 清单从 `PlatformCapabilities.importFormats` 推导，不手写第二份。

**验证**：`import_service_test.dart` 3 例 —— ico/png/jpeg 的 MIME 都在、过滤器与能力矩阵同源、每种可导入格式都有合法 MIME。

> 顺带发现：`openFile` 内部对空结果直接取 `first`，测试里无法用「返回空列表」模拟取消；因此把过滤器抽成独立方法做单测，而不是去 mock 整条 `openFile`。

---

### A3 能力位对齐

**问题**：`AppTarget.harmony` 与 `android` 共用分支，`systemSavePanel: true`。Android 现在名副其实了，鸿蒙仍没有通道。

**动作**：拆开两分支。Android `true`（SAF 已落地），鸿蒙 `false`（`share_plus` 未接，M3）。

**验证**：`capabilities_test.dart` 新增 1 例锁定该状态。

**判断依据**：S8 已经因为「能力位说 ✅、代码没有」栽过一次（SVG 三端标 ✅ 实际无光栅化）。宁可标 false 后补，也不要先标 true。

---

### A4 移动端布局守卫

**目的**：把「四页在手机竖屏下不溢出」固化成回归断言。溢出靠真机肉眼容易漏，且 M1 的页面是按桌面窗口设计的。

**动作**：新增 `test/features/mobile_layout_test.dart`，用 360×740 与 412×915 两个视口走完首页 → 导入 → 裁剪 → 尺寸 → 导出，每步 `takeException()` 断言为空。

**结果**：两个视口全部无溢出，**UI 骨架不需要为移动端重写**。这是 M2 最省事的一项——原本预估要改布局。

---

### A5 保存位置展示

**问题**：SAF 返回 `content://media/external/images/media/42`，直接显示给用户是一串噪音。

**动作**：`displaySavedPath(path, {fallback})` —— `content://` 与 null 统一显示为「你选择的位置」，桌面端照旧显示真实路径。完成态与诊断日志 SnackBar 都走它。

**验证**：3 例（content://、真实路径、null 兜底）+ 组件测试原有断言仍绿。

---

### A6 像素上限复核

**结论**：无需改动。`EditorController._process` 已读 `ref.read(capabilitiesProvider).maxPixels`，Android 自动是 32MP，超限报 `E-IMG-004`。

**未实现项**：PRD 九.3(2) 要求「位图字节与平台可用内存对比，不足则 `E-IMG-005`」。`DecodePolicy.estimateBitmapBytes` 已存在但未接入——Dart 没有读取进程 heap 上限的 API，且 32MP × 4 = 128MB 在 512MB heap 下有余量，该错误码在当前配置下不可达。记为遗留，不在 M2 硬做。

---

### A7 导出错误归类

**问题**：`export()` 只有一个 catch，把磁盘满、目录只读、文件被占用全部报成 `E-EXPORT-006`「导出失败，请尝试降低尺寸或更换格式」。用户照着这句话改尺寸，改完还是失败——因为问题根本不在尺寸。九.2 表里的 001~005 五个错误码定义了却一次都没被触发过。

**动作**
1. `services/file/file_io_native.dart` 加 `classifyFileSystemError()`：按 `FileSystemException.osError.errorCode` 归类，Windows 与 POSIX 分别查表。放在这个文件是为了跟着 `writeBytesToFile` 走条件导出，Web 编译时不会引入 `dart:io`。
2. `core/error/export_error_mapper.dart` 加 `mapExportError()`：先接 Android SAF 的 `PlatformException`（`security_exception` / `activity_not_found` / 其余），再交给文件系统归类，最后兜底 006。
3. `EditorController.export()` 的 catch 改用它。

**映射表**

| 场景 | Windows | POSIX | 错误码 |
|------|---------|-------|--------|
| 磁盘满 | 39 / 112 | ENOSPC 28 | `E-EXPORT-002` |
| 文件被占用 | 32 / 1224 | EBUSY 16 | `E-EXPORT-003` |
| 目录不可写 / 不存在 | 2 / 3 / 5 / 267 | EACCES 13 / EROFS 30 / ENOENT 2 | `E-EXPORT-001` |
| 路径非法 / 过长 | 123 / 206 | ENAMETOOLONG 36 | `E-EXPORT-004` |
| URI 授权被回收 | — | SAF `security_exception` | `E-EXPORT-005` |
| 无可用 DocumentsProvider | — | SAF `activity_not_found` | `E-EXPORT-001` |
| 归类不出来 | — | — | `E-EXPORT-006` |

**同一个数字在两端含义不同**，所以必须按端分支：13 在 Windows 是 `ERROR_INVALID_DATA`、在 POSIX 是 `EACCES`；32 在 Windows 是 `ERROR_SHARING_VIOLATION`、在 POSIX 是 `EPIPE`。用例里专门钉了这一条。

**验证**：`export_error_mapper_test.dart` 14 例，覆盖两套错误码表、SAF 三种平台异常码与兜底路径。

**未覆盖**：`E-EXPORT-005` 在 Android 上实际不可达——SAF 不需要存储权限（这正是选它的理由）。该码只在 `security_exception`（用户撤销 URI 授权）时出现，真机才能构造。

### A8 真机验收（**未执行**）

本机无图形会话也无 Android 设备，以下项**没有实测**。逐条操作步骤见 `docs/验收步骤-当前功能.md` 第 4 节（A1~A11），验收用的 Debug APK 已构建。整体结论见 `docs/M2-验收报告.md`。

| 项 | 判据 |
|----|------|
| SAF 导出落地 | 选位置后文件真实存在，系统相册/文件管理器能打开 |
| 第三方 DocumentsProvider | 选网盘类 provider 时不报错、不产生 0 字节文件 |
| Photo Picker / 文件选择器 | 能选到 ICO；选到的文件能被内容探测正确识别 |
| 32MP 边界 | 32MP 图可导入；超限报 E-IMG-004 而非 OOM |
| 小内存设备 | 中低端机 20MP 图导出不 OOM |
| 权限拒绝路径 | 拒绝后仍可用（SAF 不应申请存储权限，需确认清单里没多申请） |
| 系统返回键 | 各页返回不卡死、不丢编辑状态 |
