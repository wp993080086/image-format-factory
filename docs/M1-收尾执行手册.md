## 1. 执行原则

1. **每一步独立可验证**：`flutter analyze` 零告警 + `flutter test` 全绿 + 该步专属的验收点。
2. **不合并步骤提交**：每步完成即一次提交，便于回滚定位。
3. **先测后码**：涉及纯逻辑（几何、钳制、编码参数）时先写用例，再写实现。
4. **不扩范围**：某步执行中发现的额外问题，除非阻塞本步，一律记入「遗留清单」到 S8 统一处理。
5. **文档追平**：每步结束同步 PRD 对应章节的实现状态，不留「文档说有、代码没有」。

### S1 尺寸与比例页（PRD 三章）

**目的**：补上第三个功能页，让「改尺寸」成为可完成任务。

**规格要点（来自 PRD 三章）**

| 项 | 规则 |
|----|------|
| 自定义宽高 | 以原图像素输入；宽度或高度任一变化，另一侧按比例联动（比例锁开启时） |
| 放大上限 | 目标边长 ≤ 原图对应边 × 4，且总像素 ≤ 4000 万；超限钳制并在输入框旁提示 |
| 三种模式 | 拉伸填充（stretch，不保比例）、保持比例裁剪（cover，居中裁切）、保持比例留白（contain，补底色） |
| 留白底色 | 支持透明与自定义纯色，仅 contain 模式可选 |
| 重采样 | 默认 cubic（PRD 三.3 已注明无 lanczos）；不暴露算法下拉（MVP 简化，记入遗留） |
| 执行时机 | 与裁剪在同一次解码内完成，最后统一编码（PRD 五.6 一次编码原则） |

**动作**
1. 新增 `lib/core/image/resize_geometry.dart`：
   - `ResizeMode { stretch, cover, contain }`
   - `ResizeTarget { width, height, mode, background }`
   - `clampTarget(...)`：应用 4 倍与 4000 万像素双上限
   - `planResize(source, target)`：输出缩放 + 裁切/补白的可执行指令
2. 扩展 `EncodeRequest` 增加 `resize` 字段；`_encodeImage` 在裁剪之后、格式分支之前应用。
3. `EditorState` 增加 `resize`；`EditorController` 增加 `setResizeTarget` / `resetResize`。
4. 重写 `resize_page.dart`：预览 + 宽高输入 + 比例锁 + 模式选择 + 底色选择 + 「下一步：导出」。
5. 导出面板增加「已调整为 W × H」提示与「还原原始尺寸」。

**验证**
- 单测：4 倍上限钳制、4000 万像素钳制、三种模式输出尺寸、contain 底色填充、cover 居中裁切、stretch 变形且不裁内容。
- 编码集成：PNG 100×100 → 50×50 输出尺寸正确；contain 补白区域像素为指定底色。
- 组件测试：进入页面显示原图尺寸；输入超过 4 倍被钳制并出现提示。
- 全量 `flutter analyze` + `flutter test`。

### S2 导出参数补全（PRD 五.1、五.2）

**目的**：把压缩从「只有一个质量滑块」补成 PRD 承诺的完整参数集。

**规格要点**

| 参数 | 适用 | 默认 | 说明 |
|------|------|------|------|
| 质量 1–100 | JPEG | 85 | 已实现 |
| ~~渐进式~~ | JPEG | — | **不可实现**：`JpegEncoder` 无该参数，降级见 ADR-006 |

| 调色板压缩（PNG8） | PNG | 关 | `quantize` 后编码；**检测到半透明像素时禁用并说明**，已实现 |

**动作**

### S3 体积预估（PRD 四.7）

**目的**：导出前让用户看到「大概多大」，避免反复试质量。

**规格要点**
- 对降采样至长边 512 的临时图快速编码，按像素数外推。
- 参数变化后 debounce 300ms 触发。
- 误差可能超 30% 时（预估体积 < 50KB）标注「预估」。

**动作**
1. `EncodeService.estimate(EncodeRequest)`：复用编码链路，但先 `copyResize` 到长边 ≤512，编码后按 `总像素 / 采样像素` 外推。
2. 新增 Riverpod provider 或在面板内维护 `AsyncValue<int?>`，带 debounce。
3. 面板显示「预估 1.2 MB（源文件 3.4 MB，压缩 65%）」。

**验证**
- 单测：外推误差在已知样本上 < 30%；空请求返回 null；采样尺寸下限保护（小图不放大）。
- 组件测试：滑动质量后预估数字发生变化。
- 全量 analyze + test。

### S5 快捷键与无障碍（PRD 九.6）

**目的**：桌面端可用性达标。

**规格要点**

| 快捷键 | 行为 | 落点 | 实现 |
|--------|------|------|------|
| `Ctrl/Cmd + O` | 打开图片 | 全局 | `app.dart` 的 `Shortcuts`/`Actions` |
| `Ctrl/Cmd + S` | 导出（可编辑态） | 导出面板 | `CallbackShortcuts`，需页面内参数 |
| `Ctrl/Cmd + 0` | 视图缩放至适配 | 裁剪页 | 画布 `Focus.onKeyEvent` |
| `Esc` | 取消当前操作 / 返回 | 全局 | `AppEscapeIntent` → `router.pop()` |
| `Enter` | 主按钮确认 | 弹窗/错误卡片 | 框架原生行为，无需代码 |
| 方向键（+`Shift`） | 微调选区 1px（+10px） | 裁剪页 | 画布 `Focus.onKeyEvent` |

**动作**
1. `lib/app/shortcuts.dart`：`OpenImageIntent`、`AppEscapeIntent`、`appShortcuts` 映射，以及 `isKeyPress` / `isCommandPressed` 两个判定工具。
2. `app.dart`：在 `MaterialApp.router` 的 `builder` 里挂 `Shortcuts` + `Actions`；`Shortcuts` 内再包一层 `autofocus` 的 `Focus`，否则首页等无输入控件的地方按键无人接收。
3. 裁剪页：画布挂 `Focus`（`autofocus`、`Tab` 可入）+ `onKeyEvent`；方向键平移选区，`Shift` 步长 10，`Ctrl/Cmd+0` 适配视图；点画布顺手把焦点从输入框收回。
4. 导出面板：`CallbackShortcuts` 绑定 `Ctrl/Cmd+S`，与「导出」按钮共用同一套可用性判断（ICO 无可生成尺寸时忽略）。
5. 无障碍：画布包 `Semantics`（label「裁剪画布」+ 选区坐标 value + 方向键 hint）；全部 `IconButton` 已有 `tooltip`（复核无遗漏）。

**实现取舍**
- **`Ctrl+S` 落在导出面板而非全局**：导出参数（格式、质量、PNG 级别、ICO 尺寸）是面板内的局部状态，放全局会算错参数。
- **方向键只平移、不改尺寸**：键盘改尺寸需要「选中某个手柄」的额外语义，面板上的像素输入框已覆盖该需求，重复实现只会增加理解成本。

**验证**
- 组件测试 5 条：`Ctrl+O` 触发导入、`Esc` 返回上一页、`Ctrl+S` 直接导出（断言编码请求格式跟随源格式）、方向键 1px 与 `Shift` 10px 步长、画布 Semantics label 存在。
- 全量 `flutter analyze` + `flutter test`（210 通过）。
- 未自动化项（需真机人工确认）：正文对比度 ≥ 4.5:1、系统字号放大 1.3× 不破版。

### S6 关于页与诊断日志（PRD 十三、十六.2）

**目的**：满足上架合规与离线排障需求。

**规格要点**
- `/about`：版本号、开源许可（`showLicensePage`）、隐私说明（不收集不上传、无网络权限）、导出诊断日志。
- 诊断日志：内存环形缓冲 + 落盘，保留最近 3 次会话，单文件上限 2MB；导出为 `.txt` 走现有保存通道。

**动作**
1. 扩展 `AppLogger`：支持会话 ID、写入滚动文件（Windows）。
2. 新增 `features/about/about_page.dart`，路由注册 `/about`，首页 AppBar 加入口。
3. 诊断日志导出复用 `ExportService.save`。

**验证**
- 单测：日志超过 2MB 截断、超过 3 个会话删除最旧。
- 组件测试：关于页显示版本号与隐私说明。
- 全量 analyze + test。

**实际落地（2026-11-11）**

| 件 | 职责 |
|----|------|
| `core/log/log_ring_buffer.dart` | 内存环形缓冲，按 UTF-8 **字节**计容量，2MB 上限淘汰最旧行；单行超上限整行丢弃 |
| `core/log/log_retention.dart` | 纯函数：文件名生成（零填充、字典序即时间序）、`logsToPrune`、`recentLogFiles`，只认 `pf-*.log`，不会误删同目录其它文件 |
| `core/log/log_file.dart` + `_native` / `_unsupported` | 条件导出；原生落 `<应用支持目录>/logs`，Web 空实现 |
| `core/log/app_logger.dart` | 日志同时进缓冲 + 2 秒防抖落盘；`collectDiagnostics` 汇总当前会话与历史会话 |
| `app/app_info.dart` | 版本常量、隐私说明文案（逐条对应实现事实） |
| `features/about/about_page.dart` | 版本 / 隐私 / 许可（`showLicensePage`）/ 导出诊断日志 |

**实现取舍**
- **落盘是旁路**：任何 IO 异常都被吞掉，日志问题不得反过来影响导入/导出主流程。
- **缓冲不按级别过滤**：release 下控制台只留 warn/error，但诊断日志需要完整上下文，缓冲收全量。
- **诊断聚合抽成 `diagnosticsProvider`**：它要读磁盘，组件测试里没有 `path_provider` 通道，直接调 `AppLogger.collectDiagnostics` 会让 `pumpAndSettle` 永久挂起（实测踩到）。抽成 provider 后测试可替换。
- **未引入 `package_info_plus`**：为一个只显示一次的版本号新增平台插件违背「鸿蒙适配面最小化」，改为常量 + S8 一致性核对（记为 L-12）。
- **未做「检查新版本」**：它会是整个应用唯一的网络行为，直接与隐私声明「不申请网络权限」冲突，宁可没有。

**验证结果**：`log_ring_buffer_test`（8 例）、`log_retention_test`（7 例）、组件测试 2 例（关于页内容、诊断日志导出走保存通道）；全量 225 通过。

### S7 移动端导出通道选型（PRD 六.2、附录 #14）

**目的**：解除 M2 的硬前置，避免移动端开工时才发现无路可走。

**动作**
1. 对比三条候选：`flutter_file_dialog`（SAF）、MediaStore、`share_plus` 临时文件。
2. 核对各方案在 Android 10–15 与鸿蒙的权限与回调行为，给出结论与备选。
3. 写 `docs/ADR-007-移动端导出通道.md`（编号跳过 006，因 006 已被「渐进式 JPEG 不实现」占用），更新 PRD 六.2 与附录 #14。

**验证**
- 文档结论含：选定方案、拒绝理由、权限申请时机、失败路径、鸿蒙适配风险。
- PRD 附录 #14 标记「已结案」。

**实际落地（2026-11-11）**

**编号与位置偏离**：ADR 改为写进 PRD **十二章 ADR-007**，不另建文件。原因：ADR-001~006 全部在那里，分散到独立文件后「查一条决策」要在两处翻。

**结论**

| 端 | 通道 | 理由 |
|----|------|------|
| Android | `flutter_file_dialog`（SAF `ACTION_CREATE_DOCUMENT`） | 唯一与桌面「另存为」语义对齐；零运行时存储权限；UI 与错误处理可与 Windows 复用 |
| Android 兜底 | `share_plus` | SAF 的 `content://` 解析不出本地路径时降级（网盘类 provider） |
| HarmonyOS Next | 暂只 `share_plus` | 无 SAF 等价物，`flutter_file_dialog` 无 ohos 变体 |
| 否决 | MediaStore | 只覆盖图片集合（`.ico`/`.bmp` 不在白名单）、语义是「存相册」、老设备仍要存储权限 |

**源码级依据**：`file_selector_platform_interface 2.7.0` 的 `getSaveLocation` 默认实现回落到 `getSavePath`，后者 `throw UnimplementedError`。所以「`file_selector` 在移动端拿不到保存位置」不是猜测，是接口层面的必然。

**未决项（写入 ADR-007 的待 PoC 清单，M2 开工前必须回写结论）**：SAF 返回路径的可写性（Android 10/13/15）、第三方 provider 解析、同名覆盖行为、鸿蒙 `shareXFiles` 可用性、大文件走 SAF 与走分享缓存的耗时差。
